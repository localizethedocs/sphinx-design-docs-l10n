Change Log¶

0.8.0 - 2026-11-10¶

New components (accordion, aside, steps, vertical tab sets, and explicit card header and footer directives), links that open in a new tab, badge tooltips, a plain-CSS build with no Sass, tab selections that persist across pages and visits, accessibility fixes, FontAwesome v6 support, and Octicons v19.42.0. Sphinx 7.2 or later is now required.

Upgrade notes¶

  • Sphinx >=7.2 is required (Sphinx 7.0 and 7.1 are no longer supported); Python stays at >=3.11 (PR #276).

  • The ^^^ and +++ card separators are deprecated and warn by default. They still render as before, but the first card in a document that uses them emits one design.card_legacy warning, so a build run with -W fails until you do one of two things:

    • move the header and footer into the new card-header and card-footer directives (or the one-line :header: and :footer: options), which need sphinx-design 0.8.0 or later; or

    • add "design.card_legacy" to suppress_warnings in your conf.py.

    Once every card is migrated, set sd_card_legacy_separators = False to stop scanning for the separators. The plan is to turn the separators off by default in 1.0 and remove them in 2.0; the cards page has a migration table (PR #294).

  • Tab selections persist in localStorage instead of sessionStorage, so a chosen tab is remembered across browsing sessions as well as across pages. The storage key prefix is set by the new sd_tabs_storage_prefix option; set it to an empty string to disable persistence (PR #284, #103).

  • Static assets are served through Sphinx's html_static_path, only for HTML-format builders. A _sphinx_design_static directory left in an existing build directory by an earlier version is unused and can be deleted (PR #276).

  • The stylesheet is plain CSS, generated without Sass. The --sd-color-*-highlight hover and focus shades are now derived at runtime with color-mix() (behind the old value as a static fallback), so overriding a --sd-color-* variable now also changes its hover shade (PR #290).

  • The private sphinx_design._compat.findall helper is removed; call node.findall(...) directly (PR #276). The private CardDirective._create_component method is renamed _create_slot; the old name stays as an alias for one release (PR #294).

  • sd-card-text is added only to the direct child paragraphs of a card or dropdown body, and is added to a paragraph's classes instead of replacing them; paragraphs nested deeper (in admonitions, lists, nested tab sets) no longer get it (PR #278).

New¶

  • ✨ accordion directive: groups dropdowns so that opening one closes the others, using the browser's native <details name> behaviour with no JavaScript; :flush: renders it edge to edge by @chrisjsewell in PR #291

  • ✨ aside directive: a call-out box floated beside the body text (:align:, :width:), rendered as a semantic <aside> in HTML and a plain titled container elsewhere by @chrisjsewell in PR #292 (#97)

  • ✨ steps and step directives for numbered procedures, with CSS-only number markers on an ordered list, :start: and :color: options by @chrisjsewell in PR #293

  • ✨ card-header and card-footer directives, and :header: and :footer: options, for card and grid-item-card headers and footers: the card body is parsed once as ordinary content, and errors in a header or footer report their own line (see the upgrade notes for the legacy separators) by @chrisjsewell in PR #294

  • ✨ Vertical tab sets: tab-set and tab-set-code take :orientation: vertical, which stacks the labels in a rail beside the selected panel from the md breakpoint up by @kdeldycke in PR #304 (#219)

  • ✨ Open links in a new tab: the link-new-tab flag on card and grid-item-card, and new-tab on button-link and button-ref, for URLs and internal references alike by @dipinknair in PR #298 (#170)

  • ✨ Badge tooltips: badge roles accept a trailing ; tooltip suffix, rendered as a native HTML title; for link and ref badges it applies after the explicit text <target> form, and \; escapes a literal semicolon by @chrisjsewell in PR #286 (#81)

  • ✨ Every badge role (plain, line, link and ref, in every colour) accepts a tooltip role option, so a reStructuredText custom role (.. role:: bdg-stable(bdg-success) with :tooltip:) or an extension can preset a tooltip; a ; tooltip suffix still takes precedence by @chrisjsewell in PR #316

  • ✨ A line block in button-link or button-ref text renders as separate lines (<br /> in HTML, \newline{} in LaTeX), each line its own gettext message by @Cherith1222 in PR #308 and @chrisjsewell in PR #315 (#156)

  • ✨ A URL fragment that targets a tab (e.g. page.html#tab-name), or an element inside a tab panel, opens that tab, on load and on hashchange by @chrisjsewell in PR #284 (#239)

  • ✨ FontAwesome v6 roles (fa-solid, fa-brands, fa-regular), and CSS loading via the new sd_fontawesome_source and sd_fontawesome_cdn_url options (the supported path for FontAwesome Pro kits) by @chrisjsewell in PR #285 (#174)

  • ✨ sd_fontawesome_version makes icon role names version-agnostic: any spelling (fas, fa-solid, ...) can emit the FontAwesome "4", "5" or "6" class scheme, so upgrading FontAwesome is a one-line conf.py change; the default "as-named" keeps emitting the role name as before by @chrisjsewell in PR #288 (#174)

  • ✨ sphinx_design.testing module with the normalize_doctree_xml helper, for downstream extensions' doctree regression tests by @chrisjsewell in PR #277 (#260)

New¶

✨ Create custom directives¶

You can use the sd_custom_directives configuration option in your conf.py to add custom directives, with default option values:

sd_custom_directives = {
    "dropdown-syntax": {
        "inherit": "dropdown",
        "argument": "Syntax",
        "options": {
            "color": "primary",
            "icon": "code",
        },
    }
}

The key is the new directive name to add, and the value is a dictionary with the following keys:

  • inherit: The directive to inherit from (e.g. dropdown)

  • argument: The default argument (optional, only for directives that take a single argument)

  • options: A dictionary of default options for the directive (optional)

by @chrisjsewell in PR #194

✨ sync tabs by URL query parameters¶

Synchronised tabs can now be selected by adding a query parameter to the URL, for that sync-group, such as ?code=python for

.. tab-set-code::

    .. literalinclude:: snippet.py
        :language: python

    .. literalinclude:: snippet.js
        :language: javascript

The last selected tab key, per group, is also persisted to SessionStorage

by @mikemckiernan and @chrisjsewell in PR #196

👌 Improve dropdown title bar¶

There are three visible changes:

  1. The "default" behaviour of the right chevron is to go from right-facing (closed) to down-facing (open), instead of down-facing (closed) to up-facing (open). There is also a rotate transition on opening/closing. The old default behaviour can be retained by using the new :chevron: down-up directive option.

  2. The prefix icon (optional), title text, and chevron state icon are now all better aligned

  3. The top/bottom padding is now 0.5em instead of 1em

The PR also introduces three new CSS variables to control font sizes of the dropdown:

--sd-fontsize-tabs-label: 1rem;
--sd-fontsize-dropdown-title: 1rem;
--sd-fontweight-dropdown-title: 700;

Internally, the HTML / CSS is changed, such that the title is now an inline-flex box, with three columns arranged with justify-content: space-between:

icon (optional)

text (flex-grow: 1)

state chevron

Also, the state chevron was previously two distinct SVGs (with one hidden), but now is one that get rotated on open/close.

by @chrisjsewell in PR #192
